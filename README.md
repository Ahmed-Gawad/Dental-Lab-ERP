# 🦷 A to Z Digital Service — نظام إدارة مختبر الأسنان

نظام إدارة متكامل لمختبرات الأسنان يعمل على **ويندوز** بدون إنترنت.  
يتم بناء ملف التثبيت `.exe` تلقائياً عبر **GitHub Actions** بمجرد رفع الكود.  
عند صدور إصدار جديد، **يُخطر البرنامج العميل تلقائياً** ويعرض تحميل التحديث.

---

## 🚀 الطريقة الموصى بها: بناء تلقائي عبر GitHub Actions

> بهذه الطريقة لا تحتاج أي تثبيت على جهازك — GitHub يبني الملف نيابةً عنك!

### الخطوة 1 — تحميل المشروع من Replit
1. افتح مشروعك على **Replit**
2. اضغط على **الثلاث نقاط** (⋮) أعلى يمين الصفحة → **"Download as zip"**
3. فك ضغط الملف على جهازك

### الخطوة 2 — إنشاء مستودع على GitHub
1. افتح **https://github.com** وسجّل دخولك
2. اضغط على **"+"** في أعلى الصفحة → **"New repository"**
3. اختر اسماً للمستودع مثل: `atoz-dental-erp`
4. اجعله **Private** (خاص) للحفاظ على أمان الكود
5. اضغط **"Create repository"**

### الخطوة 3 — رفع الكود إلى GitHub
بعد إنشاء المستودع، شغّل هذه الأوامر في Terminal داخل مجلد المشروع:

```bash
git init
git add .
git commit -m "first commit"
git branch -M main
git remote add origin https://github.com/YOUR_USERNAME/atoz-dental-erp.git
git push -u origin main
```
> استبدل `YOUR_USERNAME` باسم مستخدمك على GitHub

### الخطوة 4 — بناء أول نسخة (بدون نشر رسمي)
بمجرد رفع الكود، افتح تبويب **"Actions"** على GitHub:
- سيعمل الـ workflow تلقائياً ✅
- بعد 5-10 دقائق: اضغط على الـ workflow → **Artifacts** → **AtoZ-Digital-Service-Installer**

## 🔄 نظام التحديث التلقائي — كيف يعمل؟

عندما ترغب في إصدار **نسخة جديدة** يستلمها العملاء تلقائياً:

### الخطوة 1 — رفع رقم الإصدار
في ملف `package.json`، عدّل رقم الإصدار:
```json
"version": "1.1.0"
```

### الخطوة 2 — إنشاء Tag (وسم الإصدار)
```bash
git add .
git commit -m "إصدار 1.1.0 — وصف التغييرات"
git tag v1.1.0
git push origin main --tags
```

### الخطوة 3 — GitHub Actions ينشر تلقائياً
- يكتشف GitHub الـ Tag الجديد (`v1.1.0`)
- يشغّل الـ workflow تلقائياً
- يبني ملف `.exe` الجديد وينشره في **GitHub Releases**
- يرفع ملف `latest.yml` الذي يُعلم التطبيق بالإصدار الجديد

### الخطوة 4 — العميل يتلقى الإشعار تلقائياً
عند فتح العميل للبرنامج (بعد 5 ثواني من التشغيل):

```
┌─────────────────────────────────────────┐
│           تحديث متاح                   │
│                                         │
│  تم العثور على إصدار جديد (1.1.0)      │
│  هل ترغب في تحميل التحديث الآن؟        │
│  سيعمل البرنامج بشكل طبيعي أثناء       │
│  التحميل.                               │
│                                         │
│  [ تحميل التحديث ]    [ لاحقاً ]       │
└─────────────────────────────────────────┘
```

بعد اكتمال التحميل:
```
┌─────────────────────────────────────────┐
│       التحديث جاهز للتثبيت             │
│                                         │
│  تم تحميل التحديث بنجاح                │
│  سيتم تثبيت التحديث عند إغلاق البرنامج │
│                                         │
│  [ إعادة تشغيل الآن ]    [ لاحقاً ]   │
└─────────────────────────────────────────┘
```

> ⚠️ **مهم:** نظام التحديث يعمل فقط إذا كان العميل متصلاً بالإنترنت.
> إذا لم يكن هناك إنترنت، يعمل البرنامج بشكل طبيعي دون أي مشاكل.

### التحقق اليدوي من التحديثات
من قائمة البرنامج: **مساعدة** → **التحقق من التحديثات**

## ⚙️ إعداد أذونات GitHub (مرة واحدة فقط)

GitHub Actions يحتاج صلاحية نشر الـ Releases. اتّبع هذه الخطوات:

1. افتح مستودعك على GitHub
2. اذهب إلى **Settings** → **Actions** → **General**
3. في قسم **"Workflow permissions"** اختر: **"Read and write permissions"**
4. اضغط **Save**

هذا يسمح للـ workflow برفع ملفات الإصدار تلقائياً.

## 💻 الطريقة البديلة: البناء المحلي على جهازك (ويندوز)

### متطلبات أولية
1. **Node.js 20+** من https://nodejs.org (اختر LTS)
2. **Visual C++ Build Tools** من https://visualstudio.microsoft.com/visual-cpp-build-tools/

```bash
npm install
npm run build-exe
```

## 🖥️ تثبيت البرنامج على جهاز العميل

1. انقر نقراً مزدوجاً على `A to Z Digital Service Setup X.X.X.exe`
2. إذا ظهرت رسالة **"Windows protected your PC"** → **"More info"** ← **"Run anyway"**
3. اتبع خطوات التثبيت → **Install** → **Finish**
4. سيظهر اختصار بأيقونة البرنامج على سطح المكتب 🦷

## 🔗 الربط المحاسبي بين الوحدات

البرنامج مصمم بحيث تبقى البيانات متّسقة تلقائياً دون تدخل يدوي:

- **تسجيل إيصال قبض مرتبط بفاتورة** → يُحدّث `حالة الفاتورة` تلقائياً (غير مدفوعة / مدفوع جزئياً / مدفوعة) حسب إجمالي المُحصَّل، ويُنشئ حركة "دخل" في الصندوق.
- **تعديل أو حذف إيصال** → يُعيد حساب حالة الفاتورة وحركة الصندوق المرتبطة تلقائياً.
- **تسجيل مصروف** → يُنشئ حركة "مصروف" في الصندوق تلقائياً.
- **حركات الصندوق التلقائية** (الناتجة من إيصال أو مصروف) تظهر بعلامة "تلقائي" ولا يمكن تعديلها أو حذفها مباشرة من صفحة الصندوق — للحفاظ على الاتساق، يجب تعديل/حذف الإيصال أو المصروف الأصلي.
- **حذف عميل له حالات أو فواتير**، أو **حذف فاتورة لها إيصالات**: البرنامج يمنع ذلك ويوضح السبب، لمنع تيتّم البيانات.

- جميع البيانات تُخزَّن في **قاعدة بيانات SQLite محلية على جهاز العميل فقط** (لا اتصال إنترنت، لا خوادم خارجية).
